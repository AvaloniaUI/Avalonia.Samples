This example will show you how to extend any Avalonia control and add new functionality to it. In this case we will extend the CalendarDatePicker control and add a custom parser to it as well as additional commands.

The custom parser will allow us to enter dates as relative dates, e.g. "0" for today, "-1" for yesterday, "+1" for tomorrow, etc. The additional commands will allow us to quickly set the date to today, yesterday or tomorrow.

=== Step 1: Set up a new Avalonia project

In this sample we will create a new Avalonia project and add a new custom control to it. In a real world scenario you would probably add the custom control to a shared library and reference it from your main project.

=== Step 2: Create a custom parser

We want to extend the CalendarDatePicker control and add a custom parser to it. The custom parser will allow us to enter dates in a different format than the default one. To gain a better understanding of how to extend the CalendarDatePicker control, we will first look up the API documentation of the CalendarDatePicker control. You can find the API documentation here: [https://docs.avaloniaui.net/api/avalonia/controls/calendardatepicker]. 

TIP: Avalonia is open source, so you can also grab the source code of the control you want to extend to understand how it works. You can find the source code of the CalendarDatePicker control here: [https://github.com/AvaloniaUI/Avalonia/tree/main/src/Avalonia.Controls/CalendarDatePicker].

In the link:https://docs.avaloniaui.net/api/avalonia/controls/calendardatepicker#uid-de14fbd1f9[[API docs\]] we found, that the CalendarDatePicker control has a property called `TextConverter`, which accepts an object of type `IValueConverter`. This property is used to convert the text entered by the user into a DateTime object. We will create a new class called `ShorthandDateConverter` inside the `Helper` folder, that implements the `IValueConverter` interface and add our custom parsing logic to it.

Below is a reduced version of the `ShorthandDateConverter` class. You can find the full source code of the class in the sample project.

[source,csharp]
.ShorthandDateConverter.cs
----
// Note: We need to use a partial class, because we will use a source generator to generate the regex patterns for the shorthand date formats. The source generator will generate a partial class with the same name and add the regex patterns to it.
public partial class ShorthandDateConverter : IValueConverter
{
    // A static instance of the converter for easy access without needing to create a new instance each time.
    public static ShorthandDateConverter Instance { get; } = new();
    
    // A regex pattern to match numeric offsets, e.g. "0", "-1", "+1", etc. The pattern allows for an optional "+" or "-" sign followed by one or more digits.
    [GeneratedRegex(@"^[+-]?(\d+)$")]
    private static partial Regex NumericOffsetRegex();
    
    // this method is called when the control needs to convert a DateTime object to a string for display in the TextBox.
    // culture is passed by the framework and can be used to format the date according to the user's locale.
    public object? Convert(object? value, Type targetType, object? parameter, CultureInfo culture)
    {
        if (value is not DateTime dateTime)
            return null;

        var dtfi = culture.DateTimeFormat;
        return dateTime.ToString(dtfi.ShortDatePattern, dtfi);
    }

    // this method is called when the user enters text into the TextBox and the control needs to convert it back to a DateTime object.
    // here we implement our custom parsing logic to handle shorthand date formats.
    public object? ConvertBack(object? value, Type targetType, object? parameter, CultureInfo culture)
    {
        // ensure the value is a non-empty string
        if (value is not string text || string.IsNullOrWhiteSpace(text))
            return null;

        // trim whitespace from the input string
        text = text.Trim();

        // Try shorthand formats first
        if (TryParseNumericOffset(text, out var numericDate))
            return numericDate;
        
        // ... other shorthand parsing methods can be added here, e.g., week offsets, ISO week formats, etc.

        // Fallback: try general date parsing using the culture passed by the framework
        var dtfi = culture.DateTimeFormat;
        if (DateTime.TryParse(text, dtfi, DateTimeStyles.None, out var parsedDate))
        {
            return parsedDate;
        }

        throw new FormatException($"Cannot parse the given text to a date: {text}");
    }
    
    // A private method that attempts to parse a numeric offset from the input string. If successful, it returns true and outputs the resulting DateTime; otherwise, it returns false.
    private static bool TryParseNumericOffset(string text, out DateTime result)
    {
        result = default;

        // check if the text matches the numeric offset regex.
        if (!NumericOffsetRegex().IsMatch(text))
            return false;

        // try to parse the text as an integer. If it fails, throw a FormatException.
        if (!int.TryParse(text, NumberStyles.Integer, CultureInfo.InvariantCulture, out var offset))
            throw new FormatException($"Day offset '{text}' is out of range.");

        // try to add the offset to today's date. If it fails, throw a FormatException.
        if (!DateTimeHelper.TryAddDays(DateTime.Today, offset, out result))
            throw new FormatException($"Day offset {offset} is out of range.");

        // if everything succeeded, return true.
        return true;
    }
}
----

=== Step 3: Use the custom parser in the CalendarDatePicker control

It is really easy to attach the custom parser to the CalendarDatePicker control. We just need to set the `TextConverter` property of the CalendarDatePicker control to our custom parser. This can be done in place or by a `Style` or `ControlTheme`. In this sample we will use it in place.

[source,xml]
.App.axaml
----
<!-- Remember to add the namespace of the helper class to the root element of the XAML file -->
<!-- xmlns:helper="using:CalendarDatePickerEx.Helper" -->
<CalendarDatePicker SelectedDate="{Binding SelectedDate}"
                    PlaceholderText="Enter a shorthand date"
                    TextConverter="{x:Static helper:ShorthandDateConverter.Instance}" />
----

=== Step 4: Add additional commands to the CalendarDatePicker control

You might want to further optimize the user experience by adding additional commands to the CalendarDatePicker control. In this sample we will add three commands to the control: "Set Today", "Set Yesterday" and "Set Tomorrow". These will be accessible via buttons inside the dropdown of the CalendarDatePicker control. To do this we will create a new class inside the folder `Controls` called `CalendarDatePickerEx` that inherits from the `CalendarDatePicker` control. 

==== Step 4.1: Override default values

We want our custom control to use the custom parser by default, so we will override the default value of the `TextConverter` property in the static constructor of the `CalendarDatePickerEx` class.

[source,csharp]
CalendarDatePickerEx.cs
----
public class CalendarDatePickerEx : CalendarDatePicker
{
    static CalendarDatePickerEx()
    {
        TextConverterProperty.OverrideDefaultValue(typeof(CalendarDatePickerEx), ShorthandDateConverter.Instance);
    }
}
----

==== Step 4.2: Add additional commands

We will add one additional method to the `CalendarDatePickerEx` control called `SelectDayOffset`. This method accepts an integer offset and sets the selected date to today + offset. 

TIP: In this sample we accept any object as the offset parameter and try to parse it into an integer. This allows us to use the method as a command in XAML and pass the offset as a string, e.g. "0", "-1", "+1", etc.

For the full source code of the `CalendarDatePickerEx` class, please refer to the sample project.

==== Step 4.3: Add buttons to the dropdown of the CalendarDatePicker control

In Avalonia any `TemplatedControl` needs a `ControlTheme` to define its visual appearance. In case we don't need to alter the visual appearance of the control, we can just use the default `ControlTheme` of the base class. After that, you can just run the sample and should see the control already.

[source,csharp]
.CalendarDatePickerEx.cs
----
protected override Type StyleKeyOverride => typeof(CalendarDatePicker);
----

However, we want to add three buttons to the dropdown of the CalendarDatePicker control, so we need to create a new `ControlTheme` for our custom control. We will create a new file called `CalendarDatePickerExTheme.axaml` inside the folder `Themes` and define our custom theme there. 

WARNING: Remember to comment out or delete the `StyleKeyOverride` property in the `CalendarDatePickerEx` class, otherwise our custom theme will not be applied to the control.
